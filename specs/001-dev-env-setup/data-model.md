# Phase 1 Data Model: Development Environment Bootstrap

**Feature**: `001-dev-env-setup` | **Date**: 2026-10-03 | **Plan**: [plan.md](./plan.md)

This feature has no database and no persisted domain objects. Its "data model" is three things with real structure and real validation rules: the settings loaded from the environment, the shape of committed test data, and the construction rules for generated artifact paths. Each maps to Key Entities in [spec.md](./spec.md).

---

## 1. `Settings` — validated runtime configuration

Implemented as a `pydantic.BaseModel` subclass in `src/ai_qa/config.py`, populated from `os.environ` after `python-dotenv` has loaded `.env`. Satisfies FR-021 and FR-023. The full external contract, including placeholder values, is in [contracts/configuration.md](./contracts/configuration.md).

| Field | Type | Required | Default | Validation |
|---|---|---|---|---|
| `base_url` | `HttpUrl` | Yes | — | Must parse as an absolute `http`/`https` URL |
| `browser` | `Literal["chromium", "firefox", "webkit"]` | No | `"chromium"` | Must be one of the three literals |
| `headless` | `bool` | No | `True` | Standard truthy/falsy string coercion |
| `timeout_ms` | `int` | No | `30000` | `gt=0`, `le=300000` |
| `api_base_url` | `HttpUrl \| None` | No | `None` | If set, must parse as above |
| `api_token` | `SecretStr \| None` | No | `None` | Never logged or included in `repr` |
| `artifacts_dir` | `Path` | No | `reports/artifacts` | Created if absent |
| `allure_results_dir` | `Path` | No | `reports/allure-results` | Created if absent |

### Validation behaviour

- **Fail fast, once.** The model is instantiated by a session-scoped fixture. A `ValidationError` surfaces during collection, before any test body runs, so a misconfigured environment reports a configuration problem rather than a cascade of unrelated test failures (FR-023).
- **Name the offending setting.** pydantic's `ValidationError` already includes the field name and reason; the fixture re-raises it as a `pytest.UsageError` carrying the field name and a pointer to `.env.example`, satisfying FR-023's naming requirement and SC-009's "names the missing prerequisite" bar.
- **`api_token` is a `SecretStr`.** Its `repr` is masked, so an accidental log line or failure traceback cannot print the token. This is a small safeguard, and it is the only mechanical protection in the design — the clarified decision was that secrets are kept out of version control by the `.gitignore` convention alone, with no scanning tooling.

### Why session-scoped is safe here

R6 in [research.md](./research.md) commits every fixture to function scope for parallel-safety. `Settings` is the one deliberate exception, and it is safe because the instance is **immutable** (`model_config = ConfigDict(frozen=True)`) and derived purely from the process environment. Under parallel execution each worker is a separate process with its own copy, and nothing mutates it, so there is no shared state to race on. This is recorded explicitly so a later reader does not see a session-scoped fixture and assume R6 was abandoned.

## 2. Test data files

Committed YAML under `tests/data/`, loaded via `yaml.safe_load` by a helper in `src/ai_qa/data.py`. The only use of YAML in this feature (FR-017); configuration never comes from here (FR-023).

**Shape**: a top-level mapping of named cases to case bodies. Keys are case identifiers used in test parametrisation; bodies are arbitrary mappings consumed by the test.

```yaml
# tests/data/example.yaml
valid_search:
  query: "playwright"
  expected_min_results: 1
empty_search:
  query: ""
  expected_min_results: 0
```

**Rules**:

- `yaml.safe_load` only — never `yaml.load`. Test data is committed and trusted, but `safe_load` costs nothing and removes arbitrary-object construction from the loader entirely.
- Loader resolves paths relative to `tests/data/` and raises `FileNotFoundError` naming the requested file and the directory searched.
- A file that parses to anything other than a mapping is rejected with a message naming the file, so a malformed data file is distinguishable from a failing assertion.
- No schema validation of case bodies in this feature. There are no real tests to constrain yet; adding a schema now would be inventing a contract no consumer has. Deliberate deferral, not an oversight.

## 3. Artifact paths

Not a stored entity, but the construction rule is a design commitment that FR-010, FR-024, and SC-012 all depend on, so it is specified here rather than left to implementation.

**Rule**: every generated file's path includes a component derived from the pytest node ID of the test that produced it.

```text
reports/artifacts/<sanitised-node-id>/screenshot.png
reports/artifacts/<sanitised-node-id>/trace.zip
reports/allure-results/<uuid>-result.json      # generated by allure-pytest
```

**Sanitisation**: node IDs contain `/`, `:`, and `[]` characters that are invalid or awkward in Windows paths. The sanitiser replaces each run of non-alphanumeric characters with a single `-` and truncates to 120 characters with a short hash suffix when the node ID exceeds it — long parametrised IDs would otherwise breach Windows' path limit, which matters because Windows is the primary platform.

**Collision-freedom**:

- Node IDs are unique within a run, so per-test directories cannot collide — this is what makes parallel execution a configuration change rather than a refactor (SC-012).
- Allure result filenames are UUID-based, generated by `allure-pytest` itself, so FR-024 needs no additional work (R7).

**Lifecycle**: `reports/` is created on demand, never committed (FR-018, FR-022), and is not cleaned automatically. Documenting a manual clean step is preferred over deleting an engineer's previous run evidence without being asked.
